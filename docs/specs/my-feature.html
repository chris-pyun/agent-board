사람은 맡기고 판정합니다. 에이전트는 실행합니다.

Todo
할 일 · 맡긴 일
→
In Progress
하는 중 · 하고 있는 일
→
Review
검토 대기 · 끝냈다고 올린 일
→
Done
완료 · 확인이 끝난 일

Review에서 사람 반려 → 이유를 보존하고 Todo로 이동 → 사람의 재실행 지시 → 에이전트가 이유를 읽고 재작업. 자동 재실행하지 않습니다.

1. 문제

AI가 실행한 일과 사람이 확인한 완료를 구분하고, 에이전트의 배정·판정 권한 우회와 기록 삭제를 막아야 합니다.

2. 사용자

사람: 배정·승인·반려.
에이전트: 맡은 작업 조회·시작·결과 제출.
서버: 작업별 codex exec 실행, 권한과 이력 관리.

3. 목표

사람 배정 → 에이전트 실행 → 결과 제출 → 사람 판정. 반려 이유를 재작업에 전달하고 모든 이동을 지울 수 없는 기록으로 보존합니다.

4. 범위

  • 네 열, 모든 작업의 담당자는 에이전트
  • 제목·담당 에이전트 필수, 상세 내용 선택, Todo로 생성
  • 사람의 배정·승인·이유를 포함한 반려
  • 담당 작업 조회·시작·제출만 허용하는 에이전트 API
  • 제출 결과: 작업 요약·변경 파일 목록·테스트 결과. 실패·미실행도 명시하여 Review 제출 가능
  • 서버의 codex exec 실행, 별도 OpenAI API 키 불필요
  • 실패·30분 타임아웃·취소: 결과 없으면 Todo, 제출한 Review 결과는 보존. 자동 재실행 없음
  • 에이전트별 한 작업 실행, 서로 다른 에이전트는 동시 실행 가능. 실행 중 추가 요청은 거부하며 대기열 없음
  • 누가·언제·어디서 어디로 이동했는지 삭제 불가 기록으로 저장
  • 사람 세션·회차별 토큰, 전용 OS 계정의 격리 검증 후 실제 실행
  • TypeScript·React·Node.js, 단일 로컬 서버, SQLite

5. 범위 밖

  • Backlog·미배정
  • 에이전트 자율 작업 가져가기·타 작업 접근
  • 에이전트 완료·반려 판정
  • 이동 기록 수정·삭제
  • Git 저장소·브랜치
  • 이번 문서 정리 중 코드 수정·실제 작업 실행·외부 이슈 게시

6. 확인할 시나리오

정상: 사람 배정 → 사람의 실행 버튼 클릭 → 서버가 담당 작업의 codex exec 실행 → Review 제출 → 사람 승인으로 Done.

반려: 이유 입력 → Todo 복귀 → 사람의 재실행 지시 → 에이전트가 이유를 읽고 재작업 → 결과 재제출.

예외: 에이전트의 배정·완료·타 작업 접근·기록 삭제·사람 사칭을 서버에서 거부.

7. 완료 기준

  • 네 열과 사람·에이전트 권한이 UI·서버에서 일치.
  • 결과 제출은 Review, Done은 사람 판정만 가능.
  • 반려 이유 전달과 재작업 확인.
  • 모든 이동의 행위자·시각·전이를 영속 저장하고 삭제 거부.
  • 임시 SQLite의 허용·거부 테스트와 기록.
  • 실제 CLI 연동과 API 권한 우회 방지·저장소 격리를 별도로 검증.

첫 구현: 로그인·에이전트 목록·생성·조회·영속성·감사 기록·자동 테스트. 현재는 문서 확정이며 구현과 실행 검증은 아직 진행하지 않았습니다.
